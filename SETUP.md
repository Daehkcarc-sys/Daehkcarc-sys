# Setup

This repository is a GitHub profile README. GitHub shows `README.md` on your profile page when the
repository is public and named exactly like your account: `Daehkcarc-sys/Daehkcarc-sys`.

Everything visual is a standalone SVG in `assets/`, generated by Python scripts that use only the
standard library. A daily GitHub Action regenerates them.

## Layout

| Path | What it is |
|---|---|
| `README.md` | The profile page |
| `config.json` | Name, banner text, countdown date and text |
| `projects.json` | The project cards |
| `skills.json` | The skills grid |
| `data/activity.json` | Per-day commit counts for the activity strip (written by the Action) |
| `assets/*.svg` | Generated images. Do not edit by hand; they are overwritten |
| `scripts/` | Build scripts (standard library only) and `glyphs.json`, the letter shapes |
| `tools/` | Optional local tools: PNG rendering, font extraction |
| `.github/workflows/daily.yml` | The daily rebuild |

## First-time setup checklist

1. Create a **public** repository named exactly `Daehkcarc-sys` under your account. Do not add a
   README, licence or .gitignore on GitHub.
2. Push this folder to it:
   ```
   git remote add origin https://github.com/Daehkcarc-sys/Daehkcarc-sys.git
   git push -u origin main
   ```
3. Open the repository's **Actions** tab and enable workflows if GitHub asks.
4. Check **Settings → Actions → General → Workflow permissions**. The workflow asks for
   `contents: write` itself, so the default "Read repository contents" setting is fine. If your
   account or organisation forbids write tokens entirely, the commit step will fail with a 403.
5. Run the workflow once by hand: **Actions → Daily rebuild → Run workflow**. Confirm it finishes
   green and, if anything changed, adds a "Daily rebuild" commit.
6. Open `https://github.com/Daehkcarc-sys` and check the page in light mode, dark mode and on a
   phone (see "Check on github.com" below).
7. Add your contact links in the commented block near the end of `README.md`.

GitHub pauses scheduled workflows in repositories with no activity for 60 days. The daily commit
normally keeps this one active; if it ever stops, re-enable it in the Actions tab.

## How to customize

After any change, rebuild and commit:

```
python scripts/build_all.py
git add -A && git commit -m "Update profile" && git push
```

Python 3.9 or newer is enough. Nothing needs installing.

**Edit the projects.** Change `projects.json`. Each entry has `repo` (owner/name), `title`,
`description`, an optional `note` (shown in italics: team, role, context) and `tags`. `stars` and
`language` are refreshed daily from the GitHub API; add `"language_pin": true` to keep the language
you wrote. Stars are shown once a repository has at least one. If you add, remove or reorder
projects, update the card links and alt text in `README.md` to match (`card-1.svg` is the first
entry, and so on). Only list public repositories.

**Change the countdown date.** Set `countdown.date` in `config.json` (format `YYYY-MM-DD`). The
banner and the counter both read this one value. `label`, `heading` and `line` are the text beside
the number; `label_after` and `heading_after` are used from that date onwards, when the monolith is
shown without a number. `utc_offset_hours` decides when the day changes (1 = Tunis).

**Edit the text.** Banner name and tagline are `handle` and `banner.tagline` in `config.json`;
skills are in `skills.json`. Headings, labels and numerals are drawn as paths, so they are
regenerated from these files by `build_all.py`: there is no manual path editing. The paragraph
under the banner and the section headings are plain Markdown in `README.md`.

**Preview a date.** `PROFILE_TODAY=2027-06-30 python scripts/build_all.py` builds the page as it
will look on that day. Run it again without the variable before committing.

**Render to PNG locally (optional).** `python tools/render.py out assets/header.svg` renders
through an `<img>` tag at 846px and 350px on GitHub's light and dark backgrounds. It needs
Microsoft Edge, or set `EDGE` to any Chromium browser.

**Change the typefaces (optional).** Letter shapes live in `scripts/glyphs.json`, extracted from
Cormorant Garamond and Cinzel (both SIL Open Font License). To use other fonts, download the TTF
files, adjust `FACES` in `tools/extract_glyphs.py`, then run
`pip install fonttools && python tools/extract_glyphs.py <folder-with-ttf-files>`.
`scripts/body_metrics.json` holds Georgia's character widths, used to wrap the small live text.

## The daily Action

`.github/workflows/daily.yml` runs at 23:10 UTC (00:10 in Tunis) and on manual dispatch. It:

1. refreshes stars and language in `projects.json` (GitHub REST API, public repositories only);
2. fetches 30 days of commit counts into `data/activity.json` (commit search API, public
   repositories only; counts per day, no repository names or messages);
3. rebuilds every SVG, including the countdown numeral on the banner and the counter;
4. commits and pushes only if something changed.

Security notes: it uses only the built-in `GITHUB_TOKEN` with `permissions: contents: write`, no
personal token and no secrets. The one third-party action, `actions/checkout`, is pinned to a
commit SHA. To update it, replace the SHA with the commit of a newer release tag.

## GitHub compatibility

Checked in the files:

- no `<script>`, no `<foreignObject>`, no external fonts, images, stylesheets or links inside any SVG;
- headings, labels and numerals are paths; the only live text is small body copy in
  `Georgia, 'Times New Roman', serif`;
- every SVG has `<title>` and `<desc>` (the footer ornament has a title only); every `<img>` has alt text;
- the petal animation is CSS inside the banner SVG and pauses under `prefers-reduced-motion`;
- each SVG is under 80 KB; the page totals about 410 KB.

Checked locally in Microsoft Edge, loading each SVG through an `<img>` tag (the same sandbox
GitHub uses): filters (grain, brush edges, blur) and the petal animation render, at 846px and
350px, on GitHub's light and dark background colours.

## Check on github.com

These could not be verified locally:

- **GitHub's image proxy.** GitHub serves README images through its own proxy with a strict
  content policy. Confirm the banner's petals move and the grain texture shows.
- **Firefox and Safari**, including Safari on iPhone. Only a Chromium browser was tested. Look at
  the grain, the brush-edged monolith and the petals; SVG filters differ slightly between engines.
- **Body text on phones.** Android has no Georgia, so the small text falls back to another serif.
  Lines are wrapped with a margin for this; confirm nothing runs past the right edge of a card.
- **The GitHub mobile app**, which renders READMEs with its own engine and may show the banner
  without animation.
- **Light and dark mode** on the real page: each panel carries its own dark background, so both
  should look the same apart from the page around them.
- **The first scheduled run** of the Action (the manual run in the checklist covers the logic).
